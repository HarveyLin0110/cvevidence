# CVE 調查規則庫維護

規則庫保存「這個 CVE 要查哪些條件、公告依據、排除方式與查法」。每個產品仍須重新讀取自己的材料。這些調查規則不會直接產生 Affected／Not Affected，也不會取代既有工程驗證規則。

## 從新 CVE 建立規則

1. 在網頁提交材料及 CVE，執行 AI 深度查核。沒有現成規則時，工具根據當次取得的公告建立 PC1／PC2／PC3 條件計畫。
2. 在 AI 結果展開「將這個 CVE 的查核方法加入規則庫」，下載草稿。草稿移除產品原文、產品引用和前次觀察狀態；條件文字仍須檢查是否含產品名稱、私有路徑或其他敏感資訊。
3. 維護者逐條確認公告是否支持條件、適用產品／版本、修補判別方法與必要材料。至少準備修補前、修補後、材料不足或不適用案例，留下驗證紀錄。
4. 保存覆核版本，再明確啟用。模型、上傳檔案與網頁一般使用者不能執行發布動作。

在專案根目錄執行，下列值須換成實際資料；不要把示例的覆核姓名當成已取得人員核准：

```bash
PYTHONPATH=src .venv/bin/python scripts/rule_library.py review /path/to/CVE-rule-draft.json \
  --reviewer '實際覆核者' \
  --rationale '公告、修補及各條件的核對理由' \
  --applicability '本規則涵蓋的產品、版本及限制' \
  --validation-reference '可追溯的驗證紀錄位置或編號'

PYTHONPATH=src .venv/bin/python scripts/rule_library.py activate CVE-YYYY-NNNN 覆核版本的完整rule_hash
```

`review` 只保存版本，`activate` 才改啟用指標。重複保存相同版本會拒絕覆写。覆核者欄位是本機操作者的聲明，目前不是經登入驗證的電子簽章；應由有權限的規則維護者操作。

預設保存於 `var/rule-library/`，不進 Git。可用操作者環境變數 `CVEVIDENCE_RULE_LIBRARY` 指向受管理目錄；CLI 也可在子命令前加 `--library /path/to/library`。網頁服務與 CLI 必須設定相同目錄。測試版本應使用獨立目錄，不能混入正式規則庫。

## 更新與回復

- 每次調查會重新取得公開來源，核對規則所引用 URL 的原文 hash。完全一致才使用已啟用版本，並把當次來源 ID 重新對應。
- 公告內容改變、來源未取得或規則檔損壞，都回到本次公告重新規劃，保留舊版本及原因。不能把舊規則當成已通過最新公告查核。
- 要更新，從新調查匯出新草稿並重新覆核；已保存版本不可原地修改。
- 回復時，再執行 `activate` 指向舊版本 hash；來源新鮮度核對仍照常執行，不因回復而略過。
- 接續同一案件／補件時，優先沿用該案件重新核對後的條件，逐項再 REVIEW；不在調查中途偷偷換成新版規則。另建新調查才採當時啟用的版本。

## 判定的邊界

規則中的條件與逐字公告引用仍需語意覆核。產品原文 hash 相符，只能證明讀到同一份 bytes；未必代表它屬於受查成品、實際被編入、已部署或可觸發漏洞。針對尚無可靠成品證據的案件，正確輸出是具體觀察、未解條件與最小下一步，不能為了得到明確答案而改判受影響或不受影響。
