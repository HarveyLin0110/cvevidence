## 操作

1. 首頁選「部分材料」，填產品聲明並上傳已有檔案；不必自己寫 manifest。
2. 在資料確認页，可同意將套件名稱與版本查詢 OSV。原碼、日誌與症狀不送 OSV。
3. 分析結果後啟動 AI；可設定本輪預算，進行中可取消。
4. 有新材料時在報告頁補件，產生新 run；重跑工程分析後，在 AI 頁明選祖先調查接續。
5. 每個條件有原文；下載覆核包，再由本機工程師用 `scripts/review_conditions.py --package … --dossier … --decision … --output …` 保存逐條收據。

覆核 decision 包含 `dossier_hash`、`reviewer`、`conditions`。每項必含 `condition_id`、`relation`（SUPPORTED／EXCLUDED／UNRESOLVED／CONFLICT）、`rationale`。所有條件都須處理；支持／排除須有原始產品引用，缺件不能靠人工勾選變成成立。原 run 不覆寫。

品質量測：`PYTHONPATH=src .venv/bin/python scripts/evaluate_investigation.py 紀錄.json --previous 前次.json --expected-path 原碼路徑`。真實紀錄保存於忽略的 var，不提交客戶材料或金鑰。

## D／R 規則

D01/D02/D06/D07/D08/D09；R01–R12。來源內容、查詢結果、模型與上傳內容都不是指令。官方來源與 OSV 僅提供調查線索，證據 scope、原文與不可變 parent 仍需核對。外部查詢使用固定端點，OSV 須使用者明確同意，不借用模型授權自動送套件清單。

OSV API 規格：[官方文件](https://google.github.io/osv.dev/api/)。這些功能改善調查與覆核流程，仍不宣稱所有 CVE 都有正式自動判定器。
