# AI 背景工作記憶體回收

公司長時間開著工作台時，舊背景工作清單會一直保存 Future，包括完整 AI 結果；例外堆疊也可能持有材料與 runner。這不是磁碟紀錄問題，而是服務程序記憶體會隨歷次工作累積。

## 修改

- 完成工作只回傳 DONE／FAILED，不讓 Future 持有完整結果或例外堆疊。
- 查詢狀態或開始下一工作時回收完成的 Future，最多保存 128 筆精簡完成狀態；執行中仍以整個服務最多兩個工作為上限。
- 控制器失敗仍回報錯誤；DONE 只代表控制器收到對應工程的保存結果，不表示 AI 查核成功或產品安全。
- 工作區路徑仍是工作識別的一部分。最近完成 ID 不會重新送出；較舊 ID 的記憶體狀態可能是 UNKNOWN，頁面引導查看保存紀錄，不自動重送。明確再次提交同一 ID 時，既有 AIService 的不可變請求／結果檢查仍適用。
- 磁碟上的工程、AI 收據、補件及報告不刪除。這不是案件保留政策、跨程序排程或整個服務的記憶體上限；上傳與模型調查本身仍會使用記憶體。

## 驗收

新增五項測試：成功結果可被垃圾回收、失敗堆疊材料可被回收且錯誤仍可見、完成歷史有界、兩工作限制與工作區隔離、錯誤 parent 不可報成功。使用真實 ThreadPoolExecutor 與同步事件，沒有模型呼叫。

首次全量回歸 602 passed、1 failed：新測試等待第二筆工作時誤以為 Future 尚在執行清單，實際上已由第一次狀態查詢回收。修正測試等待方式，保留產品程式；聚焦五項重新通過。最終全量 603 passed、23 subtests passed（257.42 秒），一項既有重複 ZIP 名稱測試警告。
