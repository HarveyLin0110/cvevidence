# 未讀必要條件的有界補查

真實 epsilon 對照案在第三次呼叫時，工具預估仍有三次額度、200.846 秒，模型卻直接 REPORT；map 讀取過大、關鍵迴圈與 runtime 尚未讀，並非使用者沒有提供。

## 實作

- 釐清一般 2–4 次追加調查與 PC 證據查核不同，PC 不以湊三段摘要為收尾目標。
- PC 模式的合法 REPORT 仍先核對並保存條件、引用與摘要。若共同必要條件仍 NOT_REVIEWED、沒有共同必要條件排除線索、且收齊本次回報用量後預估仍夠一次閱讀與一次收尾，先保存為部分報告並提供補查提示。
- 同次調查最多觸發一次；剩餘時間至少 130 秒（兩次既有 65 秒呼叫上限）、實際剩餘 calls 至少兩次且 token 預估足夠才啟用。用量未知不增加工作，所有原期限與停止門檻保留，不重啟調查或重置預算。
- 提示只指向尚未閱讀的必要條件及原查法，沒有預填答案、不強制升成支持／排除、不把限制轉成缺件。條件已查完、僅替代路徑未查、真正能力缺口或使用者缺件不因這個檢查延長。
- 原 REPORT 決策及完整部分結果保留，給模型的回饋另記 accepted／finalized=false 與實際預估，避免再傳同一整份條件。後續逾時仍保存部分結果；下一次 REPORT 可以如實保持未完成。
