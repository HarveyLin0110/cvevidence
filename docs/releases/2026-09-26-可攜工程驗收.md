# 可攜工程驗收

`scripts/validate_engineering.py` 原先依賴本機生成資料夾，選定 catalog 指向的資料夾已不存在；旧預期也未納入 PC3 運作證據條件。本輪改用已纳管的 demo-inputs 與 runtime-v2 封存檔，驗收前檢查封存檔大小、SHA256 及 manifest SHA256，不更改產品規則或資料包。

執行方式：在專案根目錄執行 `.venv/bin/python scripts/validate_engineering.py`。不需要 OpenAI API、重新編譯成品或舊 Demo 資料夾；報告寫入忽略的 var/validation，非公司產品驗收證書。

驗收固定要求 12 個初始案例、6 個補件案例及 5 個反向驗證，避免空集合或漏跑被當成成功：

- 原九包：有有效排除者維持 NOT_AFFECTED，缺少必要材料者維持 NEEDS_INVESTIGATION。
- 靜態證據完整的原三包與 runtime-v2 三包：除了 runtime_observation=UNKNOWN，其餘條件必須全部 SUPPORTED，不能僅靠總判定符合而掩蓋 PC2 回歸。
- 原碼／建置補件：ROM 可得到有效排除；CMake／curl 補件只補齊靜態證據，仍須保留運作缺口。
- 三種 runtime 補件：同成品、不覆寫父材料，補齊後所有條件 SUPPORTED 並判為 AFFECTED；確認 context 更新。
- 保留 value／ID／quote 竄改拒絕、使用者自述不能直接判安全、改名稱／展示時間不影響證據結果。

新增獨立 GitHub Actions engineering-acceptance 工作，與既有單元測試、隔離 ROM 讀取並行。它只讀取既有材料，不執行漏洞或交付成品。

本輪只調整驗收與 CI，沒有更改 AI、判定邏輯或網頁；未新增真實 API／瀏覽器操作。程式提交 4211fa3；本機工程驗收 12 初始、6 補件、5 反向驗證全部通過（154.966 秒），報告 var/validation/engineering-20260926T011302.json。CI 36207664059 尚在執行。本機嚴格原生 ROM 完整回歸 549 passed、23 subtests passed（298.52 秒），一項既有 ZIP 警告。
