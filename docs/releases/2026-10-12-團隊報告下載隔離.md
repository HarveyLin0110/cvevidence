# 2026-10-12：團隊報告下載隔離

公司內網試用需要驗證報告下載的帳號邊界。原 `team_app.py` 已在進入工作台前驗證登入與受邀帳號，並按 subject 分開儲存，但 `st.download_button` 會把內容登記到共用 media storage。固定的 Streamlit 1.63.0 media handler 收到已知 URL 後直接回傳內容，不再核對請求者的帳號；不可把難猜的 URL 當成案件授權。

## 修正

- 請求、工程報告、操作紀錄、公開候選、Turnkey 清單、AI 紀錄、條件覆核包、人工覆核及規則草稿，統一經 `private_downloads.download_button`。
- 帳號模式將 UTF-8／原始 bytes 以 base64 放入當前已授權 session 的 component data，由瀏覽器直接下載，不登記共用 `/media` 檔案。元件 JS／CSS 是固定程式；label 使用 `textContent`，報告不是 HTML 或 JavaScript。
- 未登入、principal 不合法、格式錯誤或超限時不提供內容，也不退回原生共用下載。本機單人入口保留原生下載行為。
- 團隊單份網頁匯出上限 32 MiB，超過會明確提示由管理員從該帳號工作區匯出；原保存紀錄不刪除。不承諾任意大小報告的瀏覽器記憶體需求。
- 不修改工程 verdict、AI 呼叫、產品材料、模型金鑰或已保存紀錄。既有 Google 登入／allowlist／帳號儲存方式保留，未開放新服務。

## 驗收與界線

14 個新增測試包括：固定框架原生 media 在沒有 cookie 時可回傳內容的重現；新團隊下載在確切原生 file ID、GET／HEAD／Range／其他 cookie 下仍不存在；不同帳號的元件 key／資料不同；未登入、非法格式、超限不公開內容；所有報告入口不繞過共用邊界。相關 109 個測試通過；最後樣式修正後的專項 29 個測試通過。

固定最終版本全量：**740 passed、23 subtests passed，321.55 秒**；一項既有重複 ZIP 檔名警告。schema 重產與 Git 一致。樣式修正前曾主動停止一輪全量（160 passed／12 subtests，exit 2），該中斷輪不列完整通過。

真正瀏覽器開啟 loopback 的 TEST_ONLY 合成帳號驗收頁：

- A、B 分別下載 `工程報告.json` 與瀏覽器自動改名的 `工程報告 (1).json`，每份 77 bytes，中文、換行及當成資料的 `<script>` 字串與各自原文逐位元組一致，沒有混用。
- 對同一活躍測試服務，以這兩份檔案的確切原生 media ID 發出共 8 次 GET／HEAD／Range／其他 cookie 請求，全部 404；未登入畫面只有拒絕訊息，沒有下載內容。
- 下載事件觀察器未回報 data URL 事件，但實際落地檔案已核對；沒有用事件逾時宣稱下載失敗或略過內容驗證。
- 此頁只模擬帳號狀態以驗證新下載傳輸，不是 Google／公司 SSO 登入端對端驗收。已授權使用者仍能儲存、轉交報告；登出不會回收先前已取得的內容。

本機 8506 重新啟動後實際載入原 curl 案件及 `20d916fe` AI 紀錄。原生下載按鈕可操作；其註冊附件端點回傳 394006 bytes，與保存紀錄完全一致。本輪未確認這份原生下載落地至 Downloads，也沒有重新呼叫模型。合成測試服務已停止，實際工作台仍只監聽本機。

可核對結果保存在被 Git 忽略的 `var/validation/private-download-20261012/`，合成測試頁不進正式入口。公司資料、帳號 token 與金鑰不進 Git。

## 部署注意

部署這個修正時，**必須完整重新啟動原團隊服務**，使舊程序已登記的原生下載檔案退出記憶體；只更新程式或刷新瀏覽器不足。仍使用 `team_app.py`、獨立持久資料目錄、HTTPS 反向代理及既有登入設定，不可公開 `runner_app.py` 的單人入口。

本機 `.env.local` 的 API Key 只供模型後端認證，不能代替網站使用者登入。目前開發 venv 沒有 Authlib；部署主機須安裝 `deploy/requirements.txt`，並以私有設定提供專用 OAuth client、cookie secret 與受邀帳號。公司實際網域、登入方式、兩個真實帳號、HTTPS callback 和伺服器仍待確認及驗收；本批未宣稱公司已上線。
