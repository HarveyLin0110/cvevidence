# 編譯資料庫與補件進展

前輪多副本查核要求 compile_commands.json，本輪補上專用唯讀解析，並實際驗證補件後能否縮小候選，而非重複要求相同材料。

## 功能與界線

依 [Clang JSON Compilation Database 規格](https://clang.llvm.org/docs/JSONCompilationDatabase.html) 讀取 directory、file、arguments／command 及選用 output。資料庫可能包含同一檔案的多種設定，保留各筆索引，不以檔名去重。commands 不執行，也不開啟宣告的主機路徑。

目前支援 POSIX 路徑的純字串正規化；依交付路徑尾段或檔名列出候選，兩份以上明示歧義。Windows／相對工作目錄尚不作對應。路徑對上不證明資料真實、編譯命令與 file 一致、建置已執行、object 已連結或同一成品採用。

最多四份資料庫，每份兩百萬 bytes、檢查前兩千筆、顯示二十筆，優先呈現公告相關原碼候選；每筆候選最多八個。超限、壞 JSON／重複鍵、無效項目、未顯示項目均保留狀態。這不是完整大型 SDK 建置圖解析，也不把未列出當成未使用。

核心候選盤點、AI 初始資料與保存結果加入同一份摘要。網頁資料確認頁新增「編譯資料庫與原碼候選（僅宣告）」面板。需要引用時仍讀原文，不將摘要 source_id 冒充 X-ID。

## 實際补件與 AI 接續

在先前 TEST_ONLY current／legacy MiniZip 案件補一份新寫的資料庫，宣告 legacy/zip.c → obj/legacy-minizip.o；檔內明示未執行，沒有 object／library／成品。補件 c64578d4-deb9-4bf5-bd1b-cc2b3754ff0d；工程 44b70d3a-de0e-4802-9bd6-9f2784df0696；接續 AI fdf8347b-9017-48aa-8344-47830bd63142。

Sol/high：5 calls、67.34 秒、161021 tokens，READ 三次、REVIEW、ASK_USER 全部成功，NEEDS_USER_INPUT。沿用並重核先前原碼引用，實際閱讀新資料庫及材料身分／註記。判讀明確指出：新增進展是「宣告選用 legacy」，仍不是編譯或最終連結完成；没有重索資料庫，下一步只有一份同 build 最終 linker map，暫不索取 runtime 或重現漏洞。

原 parent JSON bytes 與舊 AI 紀錄逐一比對不變。這是真實 API 搭配合成材料的接續驗收，不能宣稱真實公司成品已完成綁定；用量也未因呼叫較少就顯著下降。

新增解析／UI／補件測試，涵蓋宣告與實際執行分離、尾段／歧義、同檔多設定、命令不執行、資料庫與項目錯誤、範圍上限、相關項目排序、原檔變動及 parent 不變。聚焦 18 passed，最終完整 659 passed、23 subtests passed（270.30 秒），既有重複 ZIP 名稱警告一項。程式 a7f44d5。
