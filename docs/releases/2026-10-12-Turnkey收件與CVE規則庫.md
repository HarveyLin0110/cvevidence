## 1. Turnkey 材料如何交、如何補

- 依兩份 20261007 handoff 的資料分類及 v2 驗收案例新寫解析器，沒有複製舊 Demo 程式或將公司樣本放進 Git。
- 網頁可選自動辨識、2506、e5v40-01 或未知布局。先交手邊成品或來源即可；多 repo 用 ZIP／tar 保留相對目錄，不必自行製作 manifest。
- 除既有 ROM／SDK，256 MiB 大型入口也接受 MFI、ELF、link map、文字與元件清單；大型 `.txt` link map 依內容辨識。沿用原本展開、檔數、總容量與不執行上傳程式的限制。
- 保存產品家族、brand、stage、ABI、用途、host／target 的範圍線索。目錄與檔名不是已驗建置，宣告的家族若與內容不同會顯示衝突。
- MFI 僅讀有限 header、TLV、metadata 與 span：保留內嵌版本及所在 offset；SHA／contained bytes 只表示相同 bytes。未做完整解包、簽章驗證或成品採用認證。
- target `manifest.csv` 可參與元件盤點；`host-manifest.csv` 保留為 host 材料，不能抵用 target 清單，也不加入 target CVE 候選。defconfig／recipe、有效配置和 kernel Makefile 的內容版本分開保留。
- 分清「沒交」、「已交但未綁定」、「欄位不可用」、「解析器不支援」與「聲明衝突」。網頁先顯示一項優先處理事項及取得方式，其他範圍／可選材料收合；不一次要求全部原碼、部署資料或漏洞重現。
- 補件仍建立新快照，保留父紀錄。已有 target 清單時，不再次要求同一份清單；成品關聯尚未確認則明列關聯缺口。

## 2. 新 CVE 的分析與結果

沿用通用 CVE 的公告 → 條件計畫 → 讀取產品原文 → REVIEW → 收尾流程。AI 現在會取得有範圍與容量限制的 Turnkey 盤點，分辨已交未綁定材料與工具能力問題。

結果摘要依已核對的條件計畫產生，分開呈現未完成、材料衝突、工具缺口、最小補件、支持線索與排除線索；條件仍顯示必要條件、觀察、檔案及行號。若 provider 清理或外層工作流程逾時，保存摘要同步改成未完成，不保留成功樣貌。

## 3. 新 CVE 如何加入規則庫

網頁可下載條件草稿；維護者逐條覆核、保存理由／適用範圍／驗證紀錄，再透過本機 CLI 保存版本與啟用。版本不可覆寫，可指定舊版本回復；每次使用仍核對當輪公開來源的 URL 及原文 hash，來源改變或取得失敗就重新規劃。

草稿移除產品原文引用及前輪觀察，條件文字仍需檢查敏感資訊。規則只重用查核方法，不能沿用前次產品結論或自動改正式判定。接續案件優先沿用原案件條件，紀錄其來源；完成 REVIEW 後仍保留使用的規則版本。詳見 [規則庫維護](../ai/規則庫維護.md)。

下載草稿、CLI 讀取實際網頁 AI 匯出格式、保存覆核版本及啟用都已操作。測試版本只存在獨立 `var/validation/...` 目錄，沒有冒充人工核准或啟用正式生產規則。
