# 多副本搜尋與補件門檻

SDK 可能同時含已修補與舊版函式庫。原搜尋湊滿八筆命中就返回，第一份檔案內的包裝函式可能用完名額，另一份副本沒有讀取機會。實測又發現：即使看見兩份，模型仍可能只讀第一份就要求建置資料。

## 修改

- 41af4fa：搜尋先掃描有界候選，片段先各取不同檔案，再取同檔其他位置。回傳命中檔案／行數、選取範圍、未搜尋數、跳過來源與截短狀態。
- 文字掃描最多 500 個候選檔及 1600 萬 declared bytes；單檔仍限制 300 萬 bytes。這是候選掃描配額，不是包括 hash 驗證及片段重讀在內的全部磁碟 I/O 上限。命中來源清單最多 60 筆，跳過 ID 最多 20 筆，均不代表完整產品範圍。
- 89b9973：一般 CVE 調查的 ASK_USER 前檢查已回報同名程式碼副本，各副本都需有成功 READ；SEARCH 定位片段、失敗 READ 或閱讀其他檔案不能取代。適用常見程式碼副檔名，不把重複文字說明檔當成原碼副本。
- 此檢查只確認閱讀進度，不保證讀完整本文或理解語意；不同檔名的副本、超過搜尋上限或未回報來源仍可能未涵蓋。不得將未命中當成不存在，也不由此改正式判定。
