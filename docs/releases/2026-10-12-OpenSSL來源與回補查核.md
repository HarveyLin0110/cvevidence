# OpenSSL 公開來源、同版本回補與查核進度

本輪專注第二目標：能否對新 CVE 讀出具體實作及成品差異。**尚未完成任意 CVE 的品質驗收**；以下區分程式修正、實際 API 結果與未解問題。驗收跨至台灣時間 2026-10-13。原分支／PR #32 不變，origin/main 仍為 b95f96d，由 Harvey 決定合併。

## 實際發現及修改

1. CVE-2022-0778 的 CNA 仍引用 OpenSSL 舊公告與 gitweb。新增嚴格固定映射，舊公告轉現行 openssl-library.org，OpenSSL gitweb 的完整 40 位 commit 轉官方 GitHub patch；保存原始連結及來源。沒有開放任意重新導向或模型網址。
2. 本機取得的第一個 DNS 位址是不可達的 IPv6，原下載器直接放棄。改為在同一批已驗證公網位址中最多嘗試四個，共用原期限及原 hostname 的 TLS 驗證。任何非公網 DNS 結果仍整批拒絕；憑證、HTTP 狀態、內容型別及大小錯誤不靠換位址繞過。同步 DNS 本身仍不是硬性期限保證。
3. READ_BATCH 的一份大連結圖超過片段上限時，原本整批失敗，連小收據／正常輸出都未交給模型。現在逐檔保留成功的 matches；failures 明列尚未讀成者。每檔 200 行／24000 bytes、整批 48000 bytes 不變。完整性異常仍使整次操作失敗；未回傳原文不計為成功 READ，也不抵用副本查核門檻。
4. AI 已讀到原文、卻因成品綁定未查完而將所有條件保留 NOT_REVIEWED，原本無法保存 REVIEW／REPORT。現在允許保存經原文核對的 evidence_quotes 與具體進度；無摘錄或假摘錄仍拒絕，結果仍是 INCOMPLETE，不升格為支持或排除。另統一殘留的兩次收尾提示與 REPORT 預算指引。

5. 實際接續報告將「沒有憑證／ASN.1 路徑」與「已修補」一起列入優先排除。前者只是替代路徑，直接 BN_mod_sqrt 路徑仍存在。新增 `necessity=REQUIRED / ALTERNATIVE_PATH / UNDETERMINED`：只有明確分類的共同必要條件反證可優先交排除覆核；替代路徑反證不能省略其他必要查核或最小補件；共同必要條件已都有支持時，其他替代路徑的未查／缺件則保留為附帶未知，不阻擋交覆核。未知／歷史未分類先交分析端釐清，不自動補成 REQUIRED、不改舊 hash。**AI 對必要性的分類仍需語意覆核，這不是自動證明邏輯正確。**
6. 網頁及文字匯出顯示條件類型，歷史未分類結果顯示「須先釐清必要條件與替代路徑」。規則庫保留舊版本；缺分類的已啟用舊規則改為本次重新規劃，新草稿須釐清分類才能覆核發布。REVIEW 不可偷改 PLAN 的分類。
7. 兩次接續都因正常輸入 `4 17` 短於八字而拒絕報告，修正為允許完整短檔案的精確摘錄；一般文件中的短字元／單行仍不接受。核心重新核對完整檔案，不由模型自行宣稱完整。

## 受控實驗

- 公開原碼 [OpenSSL 1.1.1m](https://github.com/openssl/openssl/tree/OpenSSL_1_1_1m)，第二份只套用[官方 1.1.1n 修補](https://github.com/openssl/openssl/commit/3118eb64934499d93db3230748a452351d1d9a65)。[官方公告](https://openssl-library.org/news/secadv/20220315.txt) 同時涵蓋憑證相關路徑及直接使用 BN_mod_sqrt、參數受外部控制的應用。
- 新製兩個單一 client.elf，均實際編譯／連結，版本字串都仍是 1.1.1m。delta 是原實作；epsilon 模擬廠商維持版本字串而回補修正的情形。這是公開原碼的 TEST_ONLY 實驗，不是真實廠商／公司產品。
- 交付原碼、版本標頭、SBOM、連結圖、ELF、未簽章建置收據、正常輸入及輸出；不把答案或修補 diff 放進產品材料。產品 AI 自行從公告取得修補。
- 只執行正常質數輸入 `4 17`，沒有攻擊輸入或漏洞重現。產品內 AI 未執行成品。兩份正常輸出均回報 OpenSSL 1.1.1m。
- 首次建置因尚未產生 opensslconf.h 失敗，保存原日誌；補上官方 build_generated 後成功。核對 delta 15 個、epsilon 14 個來源／輸出／原始輸入輸出／archive／object／日誌 hash 及建置退出碼；不把 hash 相符視為公司建置身分認證。
- 下載驗證：原版本未取得允許來源；只修映射可取三份 patch，但公告因 IPv6 失敗；加入位址重試後可取官方公告及 3.0.2／1.1.1n patch，沒有下載失敗。其餘引用受三份上限限制，明列未訪問。

新 PLAN 正確分開共同必要條件與替代路徑：delta C3 為「至少一條外部可控路徑存在」，C4／C5 分別是憑證、直接呼叫；epsilon C4 為共同路徑前提，C5／C6 是兩條替代路徑。

- delta 最終 `520a9b56`：讀出版本、舊 while 迴圈、stdin → BN_mod_sqrt、靜態 archive/map 綁定聲明與正常交互。所有共同必要條件有待覆核支持，憑證分支仍未查完。LIVE 原始聚合把這條未讀替代路徑算成 INCOMPLETE；最後修正聚合後，以**同一不可變紀錄**重算展示為 SUPPORT_OBSERVED，保留 C4 未查完，沒有重寫 AI 判讀或宣稱全部路徑已讀。

- 最後的必要／替代聚合及補件邊界修正以三項新增回歸、現存 LIVE 原文重算與真正網頁驗證；沒有在此純聚合修正後再呼叫模型。前一版全量 831 passed、23 subtests passed（280.76 秒）。
- 十筆 AIStore 紀錄逐份比對保存內容與 record_hash；71 段跨紀錄關鍵摘錄重新驗證位置、原文與 file hash（不是 71 個獨立證據）；各次工程正式結果均 NEEDS_INVESTIGATION。舊無分類紀錄在新網頁標示 LOGIC_REVIEW_REQUIRED，不改歷史保存內容。
