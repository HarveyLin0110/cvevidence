# 統一成品 ELF 查核

建置關聯查核的 DT_NEEDED 讀取改用既有有界 Python ELF 解析，與材料盤點共用邏輯，不再呼叫外部 readelf。讀取前仍核對交付檔案 hash；解析能力不足或格式錯誤轉為 IntegrityError，不假裝取得空的依賴清單。無 dynamic segment 時空清單僅表示沒有該段宣告，不代表沒有靜態元件。

保留來源／object／library／產品連結查核及 PC3 運作證據要求，沒有改 CVE 條件或信任門檻。既有 archive_members 全檔讀取仍待改善，這不是整套原生解析器隔離驗收。

新增九項測試覆蓋 ELF32／64 與大小端、禁止啟動外部程序、截斷／非 ELF、無動態區段、材料變動及缺檔；與 metadata 測試合計 22 passed（3.24 秒）。

實際從 8506 網頁選擇 demo_openssl_complete_v3，匯入 CVE-2014-0160 並執行工程查核，確認受影響初判及 PC1／PC2／PC3 呈現。這是已納管展示材料，不是公司設備驗收；未新增 API 呼叫，也未執行上傳成品。

另發現舊 scripts/validate_engineering.py 指向不存在的 datasets/fresh-demo-openssl-curl-v4/packages，且舊 EXPECTED 未反映後來新增 PC3 運作證據要求；本輪未把該腳本當作通過證據。直接執行 repo 九包展示材料時，原「有影響」三包缺少 runtime_observation，保留 NEEDS_INVESTIGATION；不可為符合舊預期而降低證據要求。完整運作版本由上述網頁另驗證。

六份 ROM／curl 成品以 readelf 作驗收對照，新舊 DT_NEEDED 完全一致；readelf 僅在驗收腳本使用，產品路徑已移除。九包實跑結果保存於 var/validation/buildproof-elf-cases.json，其中三項沿用舊預期的斷言不符；查核確認三者唯一非 SUPPORTED 條件均為 runtime_observation=UNKNOWN，不能宣稱九包舊斷言通過。本機嚴格原生 ROM 完整回歸 549 passed、23 subtests passed（353.23 秒），一项既有 ZIP 警告。程式提交 922d605，CI 36207341628 尚在執行；上一輪文件 head 的 CI 36206896593 成功。只推個人開發分支，Harvey 決定合併。
