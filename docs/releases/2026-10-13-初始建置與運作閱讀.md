# 初始提供小型建置與運作原文

前次未修補 OpenSSL 調查曾在延後提前收尾後讀到實作與 map，但仍漏讀已提供、只有 80 行的 receipt，以及一行正常輸入，最終保留 INCOMPLETE。只提示繼續閱讀不足以消除這個問題。

## 修改

- 通用 CVE 調查在第一次模型呼叫前，除既有元件聲明，預讀小型建置與運作文字。候選來自當次快照的元件解析或 build／runtime／observations 等路徑線索；不依 CVE 編號、fixture 名稱或預設答案。
- 三類各限 8000 UTF-8 bytes，合計最多 24000 bytes；元件／建置各最多兩份、運作最多三份。各類最多 16 次文字讀取嘗試，避免大量不可讀檔案耗盡流程。
- 建置／運作檔案只在原檔不超過 8000 bytes、200 行時預讀全文。大檔保留 READ／SEARCH，原元件清單較大時保留先讀 60 行的既有方式，明確標示未完整讀取。
- 每份預讀記錄 X-ID、path、角色線索、實際 bytes、範圍與完整性。省略原因、數量與清單截短明列，省略不等於使用者沒提供。原文依現有 scope／hash 驗證；完整性錯誤不降格為容量限制。
- 模型可直接引用已提供的原文，不必額外 READ 相同範圍；實作與呼叫路徑仍須依當次 CVE 查讀。原文中的命令不執行，builder／同次建置／部署或語意不因預讀而被認證。
- 保存 `initial_reading` 與原始摘錄，歷史與工程判定不重寫。既有品質量測仍區分提供給模型、模型明確 READ、條件引用，沒有把自動預讀灌成額外模型查核。

## 驗收

聚焦測試 46 passed（2.93 秒），包含完整短輸入可引用、收據後段可見、來源變動拒收、UTF-8 bytes 預算、各類配額互不排擠、長檔／大檔／不可讀檔及有限嘗試、兩個 provider 不重讀即可保留部分觀察。合成測試不作真實 CVE 正確率宣稱。

已從前次 PUBLIC／TEST_ONLY 原始快照重算：delta 的收據／輸入／輸出共 2989 bytes、epsilon 共 2682 bytes，完整預讀，未加入原碼本文。完整回歸 907 passed、23 subtests passed（242.62 秒），一項既有 duplicate ZIP 警告。完整收據保留於忽略的 `var/validation/initial-context-20261013/`。

真實 OpenAI API／Sol high：未修補 delta 的六次呼叫耗時 172.986 秒、209155 tokens（停止門檻是在呼叫間檢查，最後在途回應可超過）。預讀確實讓收據及正常輸入可見，但結果為 INVALID_CITATION／INCOMPLETE：模型混寫 map 的 X-ID，兩次 REPORT 均拒收。更重要的是，當輪三份官方 patch 取得失敗，模型把舊版既有的退出檢查誤當修補，把正常輸入過度解釋成排除線索。這是實際失敗，不以引用攔截冒充語意防護，也不列為 CVE 驗收成功。下一項修改須解決修補依據與排除邊界。原工程判定維持待調查。

## 邊界

D01／D02／D04–D09、R01／R03／R05／R06／R08／R09／R10：預讀是受限原文提供，不是分析或取信規則。檔名與路徑只決定有限閱讀候選，不能產生版本／漏洞／同建置事實。預讀可能增加每次模型輸入，必須以 LIVE 的閱讀完整性與實際用量評估，不能只由 byte 差推估節費。

仍須確認模型選對實作段落、公告條件是否充分、PC3 必要性分類、可信建置及跨 CVE 穩定性。沿用 codex/horace-development／PR #32，Harvey 決定是否合併。
