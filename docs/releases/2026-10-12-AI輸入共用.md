# 2026-10-12：共用重複的 AI 調查輸入

規則庫和接續調查會在同一次模型輸入中重複附上條件計畫；已讀原文也會同時出現在初始片段、PC 證據包及接續資料。這些內容增加輸入量，沒有增加證據。

## 修改行為

- 完全相同的規則／接續條件改以 `conditions_ref` 指向 `condition_plan.conditions`；不同的條件清單仍保留。
- 已核對原文的 X-ID 在 `initial_product_excerpts` 共用一份；PC 證據包及接續資料用 `excerpt_ids` 對應。不同、即使重疊的閱讀範圍仍各自保留。
- 共用前核對原文、scope、hash、路徑；同一 ID 有矛盾或未宣告欄位時拒收，不默默丟棄。只投影送模型的初始 packet，不改不可變紀錄、供應者對話歷史或正式工程結果。
- 不新增摘要、截短或範圍合併。原本上游來源／索引的容量與截短標記仍保留。`input_compaction` 記錄前後 bytes、去除的重複數量和計量範圍，不能當成 token／費用帳單。

沿用 OpenAI API／Codex CLI 共用調查介面、原時間／呼叫／token 門檻，以及每輪重新 REVIEW 的要求。相關 D01–D09、R01/R02/R05/R06/R08–R12 涵蓋介面、來源驗證、原紀錄保留、預算、外送及輸出界線。
