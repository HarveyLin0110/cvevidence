## 五項修改與驗收標準

| 項目 | 行為 | 驗收 |
|---|---|---|
| 官方資料 | 取得政策允許的 CNA 參考、原廠公告、上游 patch，保存來源與 hash | URL／私有 DNS／大小與期限邊界；真實 curl 公告與 patch |

| 缺口分類 | 未讀完、工具能力、使用者材料、支持／排除線索與矛盾分開顯示 | 工具不足不自動要求補件；原材料索引與工程缺口折疊 |
| 最小補件 | 一個條件、1–3 項材料；含取得角色／方式、用途、替代方式與預期結果 | 過量、重複、跨條件、無用途／取得方式拒絕 |
| 先讀再問 | 先讀本次身分材料，按公告中的來源檔名排序；補件前全量比對所需路徑 | 已存在未讀、虛構已讀、未解釋現有材料不足時拒絕 |

## 真實執行與限制

使用本機 OpenAI API，設定及回報均為 `gpt-5.6-sol`，推理強度 `high`。不是開發助理代替產品 AI 回答。

- CVE-2022-35252：原 Git curl 工程包；最後程式版本 `3b837e7`，整次約 160 秒，8 calls，COMPLETED，無工具／引用錯誤。取得原廠公告與 patch，讀版本、動態連結、cookie.c 與編譯原文，提出版本與控制碼檢查的排除線索，沒有要求 PC3 補件。
- CVE-2023-38546 第一輪：從同一真實成品只交付 binary 與 SBOM，缺原碼及部署材料；約 126 秒，NEEDS_USER_INPUT。取得原廠公告與兩份 patch；只要求一份 target/link manifest，含取得方式與替代方案。
- CVE-2023-38546 最後網頁實測（程式版本 `3b837e7`）：從 `http://127.0.0.1:8506/` 實際啟動 LIVE，AI 155.595 秒、9 calls，NEEDS_USER_INPUT。只要求同一 C2 修補條件的 `source/curl/lib/easy.c`、`cookie.c`、`cookie.h` 三份檔案，各有取得方式、用途與替代方式；C3 binary 分析能力不足另標工具缺口。途中拒絕不正確公告引用、binary 文字讀取、把工具缺口當補件及虛構已讀來源，模型修正後收尾；不是每次呼叫都成功。紀錄 ID：`d390efc0-0e48-4cbb-87af-38effa2b6ffe`。
- 兩案例都保留原工程結果；正式判定仍 NEEDS_INVESTIGATION。AI 的支持／排除觀察需工程覆核，尚未新增任意 CVE 的正式驗證器。
- 來源修正後曾有一筆在總結前 TIMED_OUT，保留原紀錄。通用 PC 調查現為核心 240 秒、網頁整次 300 秒、最多 12 calls；已有三個專用 profile 維持原 145／180 秒。期限不因修正引用而重新開始。
- 本機完整原文、工程包及 API 紀錄在忽略的 `var/validation/p0-live/`、`var/runtime/`；沒有提交金鑰或完整執行資料。保留了失敗與重試，不把單次成功宣稱為所有新 CVE 的可靠度。

## 需審阅的規則與能力邊界

D01／D06／D07／D08／D09；R01–R12，特別是 R02／R03 的外部資料與受控網路、R04／R05 的調查順序與結構化檢查、R06 的不直接改判定、R09 的共享期限、R10 的既有 API 授權、R12 的安全文字呈現。

- 公告 allowlist 是目前支援範圍；未涵蓋的官方站點標示工具來源限制。新增來源需修改操作者政策，模型不能指定任意 URL。
- 引用檢查驗證存在、scope 和原文，不保證 AI 語意正確；條件是否完整、排除證據是否充分仍需覆核。
- 補件前檢查是檔案路徑匹配與原文已讀約束，不宣稱可理解所有同義檔名或所有 binary／PCAP 格式。
- 沒有自動執行上傳程式、漏洞利用或要求使用者重現攻擊。
