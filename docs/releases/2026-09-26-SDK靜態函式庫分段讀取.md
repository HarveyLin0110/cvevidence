# SDK 靜態函式庫分段讀取

程式提交 ee2a919。建置關聯查核原本用 read_bytes 讀入完整 ar 靜態函式庫，再切出各成員。本輪改用獨立 archive_reader，分段计算成員 SHA256，回傳名稱、大小與雜湊介面不變，不修改 PC 條件或正式判定。

- 每次內容讀取最多 1 MiB，檔案上限 2,000,000,000 bytes，與一般工程封存展開限制一致。
- 最多 40,000 個成員標頭、1 MiB GNU 名稱表、單個名稱 4,096 bytes、累計成員名稱 4 MiB。結果清單仍會占記憶體，不能宣稱整個流程固定只用 1 MiB。
- 支援原有一般名稱、GNU 名稱表與 BSD 內嵌長名稱；不解壓成員、不執行 object、不跟隨名稱讀主機檔案。
- 明確拒絕截斷、缺失或錯誤 padding、不合法名稱偏移／編碼、重複名稱／名稱表及超限資料，避免不完整清單參與建置判定。
- 維持不支援 thin archive。它保存外部成員參照而非完整成員 bytes，參考 [GNU ar 官方說明](https://sourceware.org/binutils/docs/binutils/ar.html)；本輪不增加外部路徑讀取。

新增 15 項案例，連同 ELF 建置測試共 24 passed（0.36 秒）。16 MiB 稀疏測試成員的雜湊與預期一致，tracemalloc 解析峰值低於 4 MiB；此數字僅適用該案例，不是整站記憶體保證。另以原生 ar 新建短／長名稱測試封存檔，確認成員大小與原 bytes 雜湊一致。

可攜工程驗收 12 初始、6 補件、5 反向驗證全部通過（176.584 秒），報告 engineering-20260926T012206.json。實際重啟 8506，從網頁匯入完整 OpenSSL 展示包並執行工程查核，確認受影響初判與 PC2 結果。本機嚴格原生 ROM 完整回歸 564 passed、23 subtests passed（331.69 秒），一項既有 ZIP 警告。CI 36208074892 的 engineering-acceptance／firmware-reader 已成功，test 尚在執行。本輪無新增模型 API 呼叫；這不等於已支援任意 SDK 格式或可信建置認證。只推個人分支，由 Harvey 決定合併。
