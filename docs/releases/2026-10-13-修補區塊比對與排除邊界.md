# 修補區塊比對與排除邊界

## 問題與處理

同版本 OpenSSL 的實測顯示：官方 patch 未取得時，模型曾把修補前既有的退出檢查誤認成回補，且過度解讀正常測試。當次報告因 X-ID 混寫而拒收，但這不是語意防護，因此新增下列檢查。

1. 公告中的 GitHub 完整 40 碼 commit／patch 及既有 OpenSSL gitweb 固定映射，改向同一 repository／commit 的 GitHub 官方 API 取 patch。URL 僅接受固定完整 commit 路徑；不接受 branch、其他 endpoint、query 或任意 redirect。無需 GitHub token，不讀憑證，不增加來源／嘗試／共用期限上限。保存實際 URL、原連結、出處及雜湊。取得失败加上有限錯誤碼，不外洩原始 exception。
2. 模型讀取當次產品來源後，工具以已保存公開 diff 比較同名候選的完整原文。檔名只選候選，不產生事實。每檔最多 1 MB、每 patch 最多 64 區塊、每側最多 200 行；逐行保留空白，不套用或執行 patch。可偵測的不完整／不支援 diff 整份拒作完整比較；原文、公開快照的雜湊重新核對。
3. 保存修補前／後的唯一匹配位置、P-ID、產品 S-ID／hash、scope 與比較 ID。全部對應區塊吻合修補後才是 AFTER_TEXT_MATCH；修補前是 BEFORE_TEXT_MATCH；混合、重複或不同保留 PARTIAL_OR_DIFFERENT。不匹配不能推論沒有等效修補。
4. 新通用調查只有 PC2 已引用產品原文的完整 AFTER_TEXT_MATCH 才能提出 OBSERVED_EXCLUSION 線索，且其他 REQUIRED PC1／PC2 條件不得仍缺件、未讀、能力不足或矛盾。這項檢查避免單憑修補原碼繞過產品身分與建置缺口；條件分類與支持語意本身仍待覆核。其餘排除方法（包含 PC1 清單缺席、PC3 正常測試／部署封閉、等效改寫）目前沒有足夠機械驗證能力，須保留 NOT_REVIEWED／CAPABILITY_GAP、具體進展與待覆核原因，不能改稱使用者缺件。這是保守的能力邊界，會減少自動接受的排除類型，不是聲稱所有方法已支援。
5. 網頁加入「公開修補與產品原碼逐行比較」，显示比對狀態與工具計算的位置。模型同樣取得比對結果；canonical READ 原文保持原格式，來源核對不受新增欄位影響。

## 可確認的範圍

AFTER_TEXT_MATCH 只表示這份保存原碼符合該 patch 全部對應區塊；不证明語意充分、實際編譯、可信 builder、同建置、產品全部副本或部署。工程正式 verdict 不變；人工或模型文字不能把它升級成「產品不受影響」。舊 run／歷史條件不重寫。正常成功只支持該筆觀測，不證明所有輸入安全或攻擊者不可達。

## 驗收

- 最後全量 **947 passed、23 subtests passed，256.20 秒**（前一階段 939 passed／261.62 秒），一項既有 duplicate ZIP 警告。schema 重產一致。包含完整前／後／混合／重複區塊、截斷／畸形 patch、容量、公開及產品竄改、正常紀錄排除拒收、固定 API 來源／媒體型態／無憑證與完整模型流程的合成回歸。合成不代表真實 CVE 正確率。

- delta：3 calls／98.492 秒／101330 tokens，COMPLETED 但調查 INCOMPLETE。取得原廠公告及兩份 patch；比較正確辨識 1.1.1 修補前區塊。模型讀取正常輸入、收據與入口，未重現「已修補」或正常測試排除錯誤；但錯選 map 的過大片段，且未讀到缺陷迴圈本體，保留 C2／C3 等未完成。不能列為完整 CVE 分析成功。
