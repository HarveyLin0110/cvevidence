# 以選項引用公告原文

前一階段真實 OpenSSL 調查，PLAN 兩次重抄 diff 引文失敗，再 READ_PUBLIC 才修正，耗掉可閱讀產品實作的額度。單加長度限制仍不能消除空白、換行或 diff 符號的抄寫錯誤，因此改為提供可選的逐字片段。

## 修改

- 送給模型的公開來源提供 `quote_options`，每段最多 600 字，保留來源 P-ID、原文、保存行位置及選項 ID。一般原碼行避免從中切斷；過長 CNA 段落可切成連續片段。選段不跨被省略的長行，截短與省略資訊仍呈現。
- 模型在新 PLAN／REVIEW／REPORT 填 `public_quote_id` 並讓 `public_quote` 留空。核心只接受本輪已提供、屬同一 P-ID 的選項，重新核對保存文字 hash，還原逐字原文後，再執行原本的條件驗證。
- 原模型參數保留；工具另記 `public_quote_selections`，保存條件仍使用原本的 `public_quote` 文字格式。舊歷史、引用、規則與 hash 不重寫；既有逐字引文仍可用。REVIEW 不能藉選另一個有效選項偷改公告依據或條件定義。
- READ_PUBLIC 也提供該保存範圍的選項，讓模型能引用初始選段未提供的細節。這只讀已保存公告，不新增網路來源或允許任意 URL。
- 編號不表示語意充分，公告也不是產品證據。正式 Assessment、產品 X-ID 驗證、缺件檢查及既有預算不改變。

初始選段仍受 6000 字來源額度控制，選項附加少量定位資訊；不宣稱每次請求輸入必然更小。目的為減少重抄與修正，須以真實查核能否讀完關鍵材料驗收。

## 驗收

先驗選項的 CRLF／空白／中文、同來源、未提供編號、文字改動、衝突引文、跨省略段、READ_PUBLIC 延伸及舊紀錄。再以新工程 run 重跑相同 PUBLIC／TEST_ONLY 案例，保留前階段失敗，不把重試當第一次成功。

全量 **884 passed、23 subtests passed**（235.15 秒，1 個既有 ZIP 警告）；schema 再產生無差異。16 個新增測試涵蓋選項完整性、相容與兩個 provider 路徑，不宣稱模擬測試已驗證真實 CVE。

兩案的保存 AI 紀錄、record hash、公開來源 hash、23 處關鍵產品原文及 30 次成功公告選取均獨立由保存快照重算核對；這是文字／位置驗證，不是人員語意核准。正式工程判定仍 NEEDS_INVESTIGATION。

本機 8506 重新載入 delta 真實紀錄，已見 PC1／PC2／PC3 的具體三段、source/bn_sqrt.c 舊迴圈、source/client.c 入口、build/client.map 綁定及 runtime 原文；網頁明確保留待工程覆核與正式需要調查。

原始收據放在被忽略的 `var/validation/public-quote-choice-20261013/`，不提交工程材料或 API 回覆。curl 新 run `62de38ef`／AI `d6a1a1e4`：7 calls、171.561 秒、235695 tokens，NEEDS_USER_INPUT／NEEDS_MATERIAL。逐段讀出 bestsub／最長尾端與完整主機名優先、hsts_add 完整主機名更新等修補線索，未誤判產品安全。一次 REPORT 因真正缺件被拒後改 REVIEW／ASK_USER；本次不是無重試。只針對 C3 提出目標輸出與同次建置 provenance 兩項，沒有要求重新交原碼或執行漏洞。最終呼叫跨過 token 停止門檻，未調高設定。

三案總計 16 calls／530308 reported tokens；40 處產品關鍵原文、42 次成功公告選取與所有保存 hash 再核對通過。curl 的來源級修補線索與成品未知分開，公告依據為 [curl 官方公告](https://curl.se/docs/CVE-2024-9681.html)。

這次解決可選公告原文的可靠提交，不宣稱分析穩定性完成。epsilon 的實際 runtime_budget 在第三次呼叫仍為 INVESTIGATE、預估 3 次可用、剩 200.846 秒，模型仍收尾；需再補有界的提前收尾控制。PC3 必要性分類、同成品可信建置及廣泛 CVE 正反例仍未完成。
