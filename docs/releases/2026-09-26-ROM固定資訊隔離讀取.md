# ROM 固定資訊隔離讀取

## 使用方式與產出

網頁「部分材料」現在可直接提交原始 SquashFS ROM。依檔案開頭辨識 SquashFS，不由副檔名判定格式。原 ROM 保留，另外生成 `.rom-inventory` 目錄內的擷取文字與 `inspection.json`。記錄包含 ROM、讀取工具、隔離工具及擷取文字的 hash，逐檔保存讀取結果。

固定讀取三個映像內路徑：`usr/lib/opkg/status`、`etc/os-release`、`etc/openwrt_release`。套件狀態可接入候選元件、Q1 及 AI 初始原文；網頁顯示部分讀取成功、不支援格式、工具未備妥或無法讀取。無法讀取不當成檔案不存在，也不會自動變成一大批補件要求。

## 執行邊界

- Linux 上需要 squashfs-tools 與 bubblewrap；CI 加入 bubblewrap 安裝。缺少依賴會保留原檔並標示能力不足，不以非隔離模式降級解析。
- 使用固定參數的 `unsquashfs -cat`，不 mount、不啟動映像、不執行其中程式、不讓模型提供命令或任意擷取路徑。[SquashFS 官方文件](https://github.com/plougher/squashfs-tools/blob/master/Documentation/4.7.4/USAGE-UNSQUASHFS.md)
- Bubblewrap 建立獨立 namespaces，唯讀掛入指定映像、讀取程式與系統函式庫目錄；不掛入工作目錄、家目錄或主機設定目錄，不共享主機網路。只有固定乾淨環境，不繼承 API 金鑰。另限制每次讀取 4 秒、每映像的讀取呼叫共享 12 秒、CPU 3 秒、地址空間 512 MiB、輸出檔 2 MiB、開檔數 64，停用 core dump。[Bubblewrap 官方參數](https://github.com/containers/bubblewrap/blob/main/bwrap.xml)
- 隔離建立失敗、映像損壞或路徑無法讀取會留下未知結果；不聲稱能區分所有解析失敗原因。這是此固定 ROM 讀取程序的界線，不代表整套 Web／AI 程式都已完成沙箱或安全稽核。
- 每次最多 3 份映像；維持部分材料每檔 20 MiB、所有材料及展開內容合計 100 MiB 的既有界線。大型 ROM 的串流收件仍待實作。

## 證據語意

hash 能核對已保存檔案與來源映像的位元組關聯，不能證明來源認證、同次建置、SDK 對應或產品 CVE 受影響。收到外部工程包時，這些 receipt 仍不是可信簽章；`provenance_verified` 保持 false。正式 assessment 未改動。

目前不是通用 ROM 完整解包：廠商容器、嵌入偏移、多分割區、其他檔案系統、ELF／函式提取以及 ROM 和 SDK／SBOM 同次建置綁定仍待補強。壓縮包中的 ROM 不遞迴自動處理。舊 Demo 只參考概念，沒有匯入其實作或材料。

## 驗收

- 十二項新測試：真實新建 SquashFS→套件與 AI 原文、hash 錯配拒絕、未知映像保留、缺工具／期限、保留路徑與數量限制、輸出界線、真實超量讀取、網頁不支援格式說明，以及四種外部 receipt 欄位錯誤。聚焦測試 12 passed（3.15 秒）。
- 真實映像含指向主機測試檔案的 symlink，確認沒有擷取該內容；只取固定資訊，映像中的測試程式未提取或執行。測試為 TEST_ONLY，不是真實公司韌體。
- 另以相同掛載及 namespace 選項、測試用 Python 程式核對隔離設定：工作目錄不可見、無法連上主機 127.0.0.1:8506、映像無法寫入、API 金鑰未繼承，四項皆通過。此輔助檢查不是對所有解析器漏洞的保證。
- 本機 8506 瀏覽器載入 `00d686a0-bc6c-4684-a78f-9589ce448490`，確認部分讀取狀態、隔離模式、ROM hash 與 curl 8.3.0-vendor2 候選；UI 無例外。本輪沒有新模型 API 呼叫。
- 最終完整回歸 **474 passed、23 subtests passed，252.86 秒**；只有既有 ZIP 重複名稱測試警告。較早未含隔離或完整 receipt 欄位檢查的回歸曾主動中止，不列完整通過；上述為最後程式完整重跑結果。
