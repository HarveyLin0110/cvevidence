# 收件失敗的原因與處理方式

此輪延續大型 ROM／SDK 收件工作，不改 PC 判定、AI 結論或正式規則。

- 部分材料收件與補件會顯示已分類的中文錯誤：上傳容量、展開容量、檔案數、損壞壓縮檔、不支援的路徑或連結，以及合併後容量。未知錯誤仍使用原本通用訊息，不將任意例外文字與伺服器路徑顯示在網頁。
- 損壞 ZIP／tar 的讀取例外轉成可處理的收件錯誤，不讓整個頁面直接崩潰。原 SDK 不需修改；只另製相關一般檔案的材料包。此輪沒有新增 SDK 符號連結支援。
- 使用 base 合併的路徑先核對總容量／檔案數，再複製舊材料，避免已知超限時仍浪費磁碟。原材料不覆寫。

新增合成材料案例驗證容量分類、損壞 ZIP、惡意路徑不回顯、SDK 內部連結、超限不複製舊材料，以及 Streamlit 表單提交後的錯誤呈現。AppTest 使用模擬上傳物件，不宣稱驗過瀏覽器原生選檔與 HTTP 上傳。

驗證：嚴格要求 ROM 原生隔離讀取的完整測試為 **490 passed、23 subtests passed**（295.33 秒），僅既有重複 ZIP 測試警告。實際瀏覽器連至 8506，切換大型材料入口、容量說明與頁面顯示正常。無新增 AI LIVE；遠端 main 無未同步 commit。
