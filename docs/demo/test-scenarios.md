# CVEvidence Demo 測試手冊
更新：2026-09-12

目前公開站可測：Google登入、情境草稿、工程包匯入、候選CVE、來源檢視、同build補件、請求/收件紀錄下載。
**完整 Q1–Q5、工程判定、AI LIVE 與其分析報告尚待接線；下列文字是測試輸入，不是預先產生的分析結果。**

## 1｜最快開始：只描述情境
資料來源選「先描述情境」，CVE留白，貼上：
```text
我們的工業設備在匯入更新檔時失敗，log 顯示「gzip stream ended before trailer」。
目前還沒有確認產品版本、zlib 版本及成品 hash，也尚未取得工程包。
請先列出需要補齊的產品資訊與工程材料，區分檔案不完整的可能性與漏洞適用性，不要只憑錯誤訊息判定 CVE。
```
按「匯入並建立查核」。
應看到：DRAFT、資料需求引導、「為此草稿補上工程包」與請求下載。**不應出現漏洞判定或AI已完成。**
此例已在公開站實測成功。

## 2｜主展示：ROM 缺件 → 來源查核 → 補件
選「產品／版本樣品」中的 fresh-rom · 03_rom · fresh-rom-r2。
CVE欄：
```text
CVE-2014-0160
```
情境欄：
```text
掃描報告指出設備韌體包含 OpenSSL 1.0.1f，請確認 CVE-2014-0160 是否適用本次交付的成品。
目前只有 ROM 與部分 SDK，尚不確定 heartbeat 的編譯設定、libssl 與產品的實際連結關係。
請以本次成品及 build 為範圍，列出已知證據與需要補齊的材料；版本命中不能直接視為受影響。
```
匯入後按下一步。檢查產品/build、來源列表及缺件；來源搜尋可輸入：
```text
SSL
```
到報告與後續行動頁，用補件入口選 supplement_03_rom；不要當成新的初始工程包。
應看到：補件產生新run/parent關係，舊紀錄保留，來源增加。最終判定要等完整工程接線，不能用03/02檔名代替證據。

## 3｜CMake：從異常找候選
選 fresh-cmake · 06_cmake · fresh-cmake-r2，CVE先留白。
```text
客戶匯入更新檔失敗，log 顯示 gzip stream ended before trailer。
請先檢視本次產品、元件清單及 build 記錄，找出有來源依據的候選 CVE。
我想區分下載或解壓檔案不完整，與 zlib 相關漏洞是否適用；目前沒有證據能確認這個錯誤是漏洞造成。
若缺少產品 source、compile/link 記錄或 linker map，請明確列出。
```
應看到：根據包內材料呈現候選及來源，候選不等於判定。
之後指定查核時可用：
```text
CVE-2022-37434
```
來源搜尋可用 inflate。同build補件選 supplement_06_cmake。截短gzip錯誤不能宣稱已重現漏洞。

## 4｜curl：SOCKS5 更新下載
選 fresh-curl · 09_curl · fresh-curl-r2。
CVE欄：
```text
CVE-2023-38545
```
情境欄：
```text
這個產品透過 SOCKS5 proxy 下載更新，現場偶爾出現握手延遲。
請查核 CVE-2023-38545 是否適用本次交付的下載工具。
目前不確定 DNS 解析位置、實際 hostname 長度、buffer 設定及產品是否連結到該份 libcurl。
請先核對 launcher/config、元件及成品綁定；正常下載成功不能單獨證明不受影響。
```
來源搜尋可用 socks；補件選 supplement_09_curl。
應看到來源與缺件，不應把「握手延遲」直接寫成漏洞原因。

## 5｜一個工程包、兩個 CVE
選06_cmake，CVE欄：
```text
CVE-2022-37434, CVE-2014-0160
```
情境欄：
```text
請以同一份成品快照分別追蹤這兩個指定 CVE。
每個 CVE 應有獨立查核紀錄；若元件或證據不適用，請保留缺口，不要沿用另一個 CVE 的結論。
```
應看到一個請求、兩個不同子run，archive一致，CVE分開。這是流程隔離測試，並不是聲稱本產品同時有兩個漏洞。

## 6｜邊界測試
| 操作 | 預期 |
| --- | --- |
| CVE輸入 hello | 顯示格式問題，不建立成功分析 |
| 一次輸入6個CVE | 提示最多5個，不悄悄略過第6個 |
| 只填情境、不給工程包 | 保存DRAFT，不產生漏洞判定 |
| ROM父run補上CMake補件 | 拒絕不同build補件，原run保留 |
| 重新載入自己的請求 | 維持原request/run識別，不改舊內容 |
| 登出 | 回登入頁，不能繼續操作工作台 |

第6個CVE測試文字（只測數量限制，不代表支援這些CVE）：
```text
CVE-2014-0160, CVE-2022-37434, CVE-2023-38545, CVE-2021-44228, CVE-2017-0144, CVE-2024-3094
```

## 選檔與受控路徑
最快用產品樣品，不必另外下載。若測上傳，使用repo的 demo-inputs/rom、cmake、curl 中 .tar.gz 原檔。
補件檔只能走補件入口。不要重新壓縮或改內容，否則catalog hash會不同。
「受控路徑」是**網站伺服器的受控資料目錄相對路徑**，不是你電腦的 C:\\Users 路徑；公網使用者請優先選樣品或上傳。
此站單次上傳上限32MB，目前正式12個樣品均在此限制內。

## 建議展示順序
先測1確認草稿 → 測2走ROM主流程 → 測3展示無CVE入口 → 測5展示多CVE隔離 → 測6確認不亂判。
待工程接線完成後，再验Q1–Q5、SUPPORTED/BLOCKED/UNKNOWN、判定依據及補件後差異。
AI LIVE需另外驗證實際模型呼叫、引用、超時與失敗；不能因網站在線就標成AI LIVE成功。
