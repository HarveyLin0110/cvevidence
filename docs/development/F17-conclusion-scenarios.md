# F17：情境、結論與證據邊界
日期2026-09-12。Frankie；本輪是呈現設計，不修改核心規則。新增核心契約仍須Horace覆核。

## 目的
每項SUPPORTED只支持該條件；工程Affected不等於已重現、外部部署可利用或事件已歸因。
「未提供重現結果」與「已執行測試但未觀測到漏洞」也不同。使用者需看到證據強度與尚待確認問題，不能把所有未知合成安全或危險。

## 情境與應有結論（設計矩陣，不由前端重新判定）
| 證據情境 | 工程適用性的合理表達 | 重現／部署的合理表達 | 下一步 |
|---|---|---|---|
| 僅Scanner／SBOM版本命中 | 候選關聯；不足以判定本次成品受影響 | 未提供獨立證據 | 核對實作、修補、build及連結 |
| 僅正常連線／正常功能測試成功 | 不足以支持漏洞安全或適用性結論 | 正常功能觀測；不等於漏洞重現 | 查核具體觸發條件及可靠工程證據 |
| 只有原始碼／symbol／函式存在 | 有相關實作線索，成品綁定／可達性可能仍未知 | 未提供重現或部署結論 | 核對同build編譯、連結與路徑 |
| 核心所需工程條件均成立且範圍綁定完整 | 可為Affected工程初判，以核心保存結果為準 | 仍不可稱已重現／已遭利用 | 修補／緩解與工程覆核；重现非判定必要前置 |
| 可靠必要條件阻斷，範圍及綁定完整 | 可為NotAffected，限本成品及CVE | 不能推廣所有部署／其他CVE皆安全 | 保留阻斷依據與適用範圍 |
| 宣稱停用功能但沒有可靠build／配置證據 | 仍需確認；文字聲明不能取代驗證 | 部署配置待核對 | 補同build紀錄與實際配置 |
| 核心必要證據缺件／互相矛盾 | NeedsInvestigation；列具體缺口／矛盾 | 不把未知轉為否定 | 補件後新快照重判，保留舊紀錄 |
| 有測試但沒有成功觀測漏洞 | 單次未重現不推翻完整工程證據 | 僅該環境／測試條件未觀測到；不得稱安全 | 核對測試有效性、覆蓋與環境一致性 |
| 有同成品漏洞重現且具備可覆核紀錄 | 需核心覆核重現與工程證據的一致性 | 僅通過覆核的測試範圍可標已重現 | 保存輸入/環境/成品hash/觀測/覆核身分 |
| 工程Affected但聲稱外部不可達 | 工程初判不自動變NotAffected | 暴露需獨立配置／網路／權限證據 | 分開記緩解措施與成品適用性 |
| 重現／部署觀測與既有工程結論矛盾 | 保留原結果並標待核心覆核，不能前端自改 | 明確列相互矛盾的範圍與證據 | 查核build/context/環境及規則充分性 |
| 未支援CVE／執行或完整性失敗 | 尚無有效工程判定，不是假安全 | 無可用分類結果 | 修正輸入或補受審查profile |

## 本輪已實作
結果摘要與文字報告共用三個面向：工程適用性、漏洞重現、部署暴露與實際利用。
工程結論取原assessment；後兩者目前沒有獨立受驗證欄位，顯示「尚無獨立覆核結論」，而非「未重現／不可利用」。
條件表把SUPPORTED改為「支持此項工程條件」，並加證據邊界。trigger_prerequisites明示不代表實際觸發；entry_reachable明示不代表部署外部可達。
不讀檔名、自由文字或模型輸出推斷已重現；不新增假的confidence百分比。
