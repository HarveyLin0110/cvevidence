## 安裝及開啟本機網頁

使用 Linux 或 Windows 的 WSL2，建議將 checkout 放在 Linux 檔案系統。CI 使用 Python 3.12；POSIX worker 與韌體隔離工具不能以原生 Windows Python 直接代替。

Ubuntu／Debian 系列的新環境可依序執行：

```bash
sudo apt-get update
sudo apt-get install -y git python3 python3-venv build-essential binutils squashfs-tools bubblewrap
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pip install -e .
.venv/bin/python scripts/workspace_service.py start
```

瀏覽器開啟 <http://127.0.0.1:8506/>。`runner_app.py` 是目前實際分析工作台；`apps/web/` 是比賽 UI 模擬稿，接續後端與網頁開發應從前者開始。

新環境的歷史列表為空是正常的，執行時會建立 `var/runtime/`。可使用已入 Git 的 [demo-inputs](../../demo-inputs/README.md) 建立新案件，不必先產生舊筆電的 runtime 或重新編出所有 Demo。

更新 Python 程式後用下列指令重啟，避免混用舊程序；AI 模式請使用下一節的啟動方式：

```bash
.venv/bin/python scripts/workspace_service.py restart
.venv/bin/python scripts/workspace_service.py status
```

韌體 reader 需要環境允許 bubblewrap／user namespace；受限環境可能只能保留原檔並顯示能力不足。不要為了讓畫面看起來成功而移除隔離。相關環境驗收命令已在 [CI workflow](../../.github/workflows/tests.yml)。

## AI 深度調查需要新環境的認證

本機網頁、收件與既有工程規則可以先使用；真實 AI 調查另外需要 API 金鑰、模型權限與網路。Git clone 不會帶入原筆電的 API／GitHub／Codex 登入。下載新 CVE 公告等公開來源也需要網路。

以下適用新 clone，先建立私人設定檔：

```bash
cp .env.example .env.local
chmod 600 .env.local
```

用編輯器在 `.env.local` 填入新環境有權使用的 key。原實測使用的設定為：

```dotenv
OPENAI_API_KEY=填入自己的有效金鑰
OPENAI_MODEL=gpt-5.6-sol
OPENAI_REASONING_EFFORT=high
```

`.env.example` 預設推理強度是 medium；要延續本輪 high 設定需自行修改。模型是否可用以新帳號權限為準。環境變數會優先於設定檔，若畫面與檔案不同，也要檢查啟動 shell 的設定。金鑰不要提交或貼到 PR。

```bash
.venv/bin/python scripts/start_local_ai.py
```

此腳本載入私人設定、啟用 API 調查並重啟本機 8506；仍由使用者在網頁確認後才執行付費模型調查。一般 `workspace_service.py restart` 不會自行載入 `.env.local`，AI 模式重新啟動仍使用 `start_local_ai.py`。Codex CLI provider 是另一條可選路徑，不是啟動上述 API 路徑的必要依賴；本輪最新 LIVE 驗收使用 API。

## 不隨 Git 搬移的內容

- `.env.local`、備份 key、登入憑證：新環境自行設定，不是缺少程式。
- `var/runtime/`、原始 LIVE 收據與 `var/validation/`：舊案件與本機實驗不隨 clone 還原；Git 留有驗收摘要，但不能宣稱原始歷史可在新機直接開啟。
- 兩份 Downloads Turnkey handoff 及公司樣本：不在公開 repo。一般開發與 repo 測試不依賴它們；重做那 23 項公司 handoff 驗收時，需由公司另行提供允許使用的材料。
- 正式調查規則庫 `var/rule-library/`：本機未啟用生產規則；TEST_ONLY 規則不冒充正式發布。新環境依維護流程建立受管理目錄。
- `.venv`、build／快取及舊工作樹：依依賴與程式重建，無需搬移。舊 101 筆重整前歷史與零散實驗分支不是現在開發基準；目前整理後成果已在遠端分支。
- 本機未追蹤 V4 規劃與 9 月 12 日 Host/API 提案是歷史草稿，非必要缺件。Git 已有 V5 規劃、正式程式與最新交接，不依賴這兩份舊檔。
