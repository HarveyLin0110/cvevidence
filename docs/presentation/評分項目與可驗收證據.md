## 六分鐘可用的重點順序

1. 收到 CVE 通知但供應商只說已停用：ROM 03 先查，再補回 02 同次建置原檔，條件充分才轉 Not Affected。
2. 展開 AI 新增的 library 對應問題與實際唯讀工具紀錄，讓評審能打開引用。
3. CMake 從 gzip 截短讀取錯誤開始，找有來源的 zlib 候選；清楚說明截短錯誤並非 CVE 已觸發。
4. 用 curl 修補/使用條件及九格實測表補充適用範圍，下載可追查摘要。
5. 展示一筆今日 Codex「失敗 → 根據紀錄修正 → 重測」證據。

## 成績表必須分開計數

- 六個新 build：只有完成命令、產物 hash 及正常功能觀測才計數。
- 九包資料：manifest、archive、hash、同 build 補件關係驗過才計數。
- 九格工程判定：實際 collect/verify/assess 跑完，對照獨立驗收預期才計數。
- 三條補件：保留原 run，核對同一成品，新增快照重算才計數。
- Live AI：至少三次實際 OpenAI 呼叫與工具/補件紀錄，另外記失敗、耗時與模式。Offline 或 Replay 不計為 Live。
